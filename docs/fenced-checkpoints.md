# Official PostgreSQL checkpointer transaction adapter

FencedPostgresSaver composes the public AsyncPostgresSaver3.2.0 interfaces. Every aput/aput_writes obtains a checkpoint-role connection and opens an outer transaction. The restricted guard verifies current Actor,tenant,topic,run revision,execution owner/token,unexpired lease/deadline and immutable thread/empty namespace; it locks identity,conversation and run in the same established order. The exact same connection is passed to the official saver. A second guard and checkpoint digest update execute before that outer transaction commits. Checkpoints,blobs,pending writes and digest therefore roll back together. A pool-backed writer is never called after a separate state check.

Official setup runs only as maintenance owner with autocommit=True,dict_row and fixed graph_checkpoint schema. Runtime ip_checkpoint can call only the protected guard and write its own checkpoint tables; it cannot directly change run state,permissions or budgets. Read/list operations verify the same thread ownership and current authority. Lists are bounded and buffered before yielding so consumer waits cannot retain authority locks.

checkpoint_scope uses a ContextVar carrying server-created Actor/Fence/thread; graph state does not carry reusable authorization or bearer credentials. Concurrent runs can share a saver without sharing identity. Background runs remain attached to their original topic even while another topic is active. Foreground execution still obeys its conversation epoch through the common execution guard.

The adapter enables project-process LANGGRAPH_STRICT_MSGPACK and explicitly uses a serializer allowlist with pickle_fallback=False. It admits JSON values,official Interrupt values,and sanitized builtin retry-error codes; arbitrary dataclasses/custom constructors,Delta channels,copy,delete,prune and runtime setup are refused. An SDK mutator audit fails tests if an upgrade introduces a new write interface. No permissive fallback is provided.

Actual acceptance tests use official PG tables. They cover expired A with no B,late A checkpoints and pending writes after B,post-write injected rollback of all tables,P03 takeover blocked by A's run lock,the database ending A's idle transaction,and revocation in both orders. A minimal real LangGraph graph is interrupted in process1,approved using the digest written by the official adapter,and resumed in process2 with a new lease. Its calculation counter remains1. Final graph checkpoint is saved while the run remains RUNNING; the Worker will commit the final report afterward.

The digest chains committed official checkpoint/pending-write payload hashes under the run lock. Human approval compares the current digest and persistent budget snapshot at consumption. An accepted resume may write later checkpoints; query execution then uses the consumed approval bound to that query/revision rather than requiring the old checkpoint hash to remain current forever.
