# MCP data resource server

SDK2.3.0 MCPServer serves stateless Streamable HTTP at /mcp. The native entrypoint and Docker use the same server. Lifecycle opens bounded database pools once per process and closes them with the SDK session manager. Live/readiness endpoints make no model request. The server publishes only list_datasets,get_metric_definition,validate_query,execute_query; no arbitrary resource, shell, network or token-issuance tool exists.

The worker internally issues60s HS256 capabilities with fixed issuer https://insightpilot.local/ and audience https://insightpilot.local/mcp. These URLs are identifiers for the internal capability protocol; this project is not a public OAuth authorization server. Signature, issuer,audience,exp,nbf,iat,jti,base scope and per-tool scope are checked. Current identity/version,run owner,topic,revision,execution token and unexpired database lease are checked again. Tokens cannot outlive authority just because their signature is valid.

Actor and RunFence come from the SDK's verified AuthContext ContextVar. Tool arguments never contain tenant,user,role,DSN,auth_version or lease token. A strict pre-handler middleware rejects unknown/non-scalar fields because the SDK's default argument model otherwise ignores extras. Public input schemas use additionalProperties:false. Every tool rechecks current database authority, including catalog reads. Simultaneous identities share a pool, not an identity variable.

DataToolsClient uses the SDK's actual HTTPX2 transport, initializes a real HTTP session and validates structured results. Its endpoint is restricted to loopback or the fixed Docker mcp:8011 service; redirects and environment proxies are disabled. Calls fit the remaining persistent execution deadline. Known transport exception groups and unavailable state dependencies become safe503 domain failures. Unexpected programmer failures are not turned into successful data. Neither bearer values,passwords nor raw sensitive SQL parameters are included in error envelopes.

SDK2.3 Python attributes are snake_case (is_error,structured_content,input_schema); protocol JSON retains camelCase aliases. HTTPX0.28 remains for existing API/browser tests; HTTPX2.16 and mcp-types2.3 are explicitly pinned for this protocol. Tests launch a separate owned child process at a random127.0.0.1 port, use official ClientSession over HTTP, run actual PG queries, and exercise401/403,forged args,revocation,two-tenant concurrency and refused connections. No stdio/in-memory substitute is counted as HTTP verification.
