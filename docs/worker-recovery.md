# 后台执行、准入和恢复

`insightpilot.cli worker` 独立进程运行两个前台轮询 lane、一个后台 lane 与独立回收循环。实际任务只由 PostgreSQL 持久状态领取；Redis 提醒不是调度真相。每个任务通过数据库单调 execution_version、owner、60 秒租约及当前授权控制提交，10 秒独立续租，不在网络请求期间持有授权事务锁。

执行槽和模型槽分开；Redis TIME/Lua 原子限定每类总并发最多 2、后台最多 1，前台至少保留 1。槽为唯一 token + owner，TTL 60 秒，续期不会复活已过期 token；模型 HTTP 单次不超过 45 秒。Redis 不可用时拒绝准入。每个图节点、后续模型/工具操作检查当前执行名额；名额或租约丢失停止后续动作。限制针对项目内同时活动的客户端请求，不宣称供应商在客户端断开后立即终止计算，也不承诺外部调用恰好一次。

前台排队 60 秒/执行 120 秒，后台排队 600 秒/累计活动执行 300 秒；当前领取开始计算固定 active_deadline，调用、目录读取、工具、槽等待和重试均计入。人工等待最多 24 小时，暂停保存剩余秒数、释放租约与名额；显式恢复原任务不增加自动重试次数。自动执行最多总共 3 次，失败后分别等待 5/30 秒，调用/查询/修复预算不重置。取消、撤权、永久错误不重试。过期回收先筛选到期或失效行，再作最多 100 条锁定检查，避免未到期任务饿死后来过期任务。

Worker 从官方 PostgreSQL 检查点恢复：已有完整报告则复核并发布；未完成节点重跑；interrupt 仅消费数据库已绑定决定。每次澄清包含独立 nonce，旧答案不能套用到新的澄清。最终报告在同一数据库事务内重新加载证据、检验 SQL/数据版本并锁住当前授权与活动数据版本；提交报告、助手消息和完成事件原子发生。

系统测试用真实 PG/Redis/MCP/HTTP 模型与两个独立 Worker PID。Windows 测试直接启动项目管理的基础解释器并加载该项目虚拟环境的 site-packages，核验实际 PID 后仅暂停/恢复本次 Popen 句柄；Linux 使用同一子进程 SIGSTOP/SIGCONT。故障点在真实 SQL/证据提交后、图 pending write 前。测试明确注入专属 run 租约和 owner 的 Redis 过期，不伪称等待了 60 秒；覆盖恢复旧进程和强制退出两种情况。证据文件记录实际 PID、版本变化、命中的故障、旧提交计数、查询预算及最终报告数。
